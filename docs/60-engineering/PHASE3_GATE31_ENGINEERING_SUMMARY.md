## Migration summary

**Enums:** `public.provisioning_job_state` (13 values, mirrors `lifecycle.ts`), `public.provisioning_step_status` (6 values).

**`public.provisioning_jobs`** — `tenant_id`, `state`, `current_step_key`, `attempt_count`, `correlation_id` (NOT NULL), `provider_key`, `provider_resource_reference` (jsonb), `last_error`, `started_at`, `last_transition_at`, `completed_at`, audit columns. Indexes: `state`, `tenant_id`, `correlation_id`, and a partial unique index enforcing **at most one non-terminal job per tenant**.

**`public.provisioning_steps`** — `job_id` (cascade), `step_key`, `sequence`, `status`, `attempt_count`, `correlation_id` (NOT NULL), `error`, `started_at`, `completed_at`, `duration_ms`, audit columns, unique `(job_id, step_key)`. Indexes: `job_id`, `status`, `correlation_id`. `duration_ms` is computed by trigger on completion.

**Security:** `GRANT` to `authenticated` and `service_role` only (no `anon`); RLS enabled; SELECT/INSERT/UPDATE policies gated on `private.fn_has_role(auth.uid(), 'admin')`.

Platform database only. No tenant-database objects were created.

## D1 mitigation (risk closed)

`public.tenants.provisioning_status` is now a **derived column**:

```text
provisioning_jobs.state
        │  private.fn_derive_tenant_provisioning_status (IMMUTABLE)
        ▼
trg_provisioning_jobs_sync_tenant_status (SECURITY DEFINER, BEFORE INSERT OR UPDATE OF state)
        ▼
tenants.provisioning_status
```

- `src/lib/provisioning/status.ts` is the TypeScript mirror of the SQL function; `status.test.ts` asserts the mapping for all 13 states.
- The same trigger maintains `last_transition_at`.
- `COMMENT ON COLUMN public.tenants.provisioning_status` records that application code must never write it.
- No application code writes the column — verified by repository search.

## Architecture / ADR compliance

| Requirement (ADR-018) | Evidence |
| --- | --- |
| Two separate lifecycles | Tenant lifecycle untouched; provisioning lifecycle is its own module and enum |
| Provider abstraction / dependency inversion | `provider.ts` is interface-only; no SDK, no HTTP, no vendor import anywhere in the module |
| Secrets never in source | Only `SecretReference` (name + scope) exists; no credential values, no secret store |
| Retry policy | Pure classification, budget, capped exponential backoff with injectable jitter |
| Rollback policy | Reverse-order plan, eligibility, orphan handling — planning only |
| Migration strategy | `MigrationRecord` type + provider `applyMigrations` contract |
| Idempotency | Migration guarded with `IF NOT EXISTS` / `DROP POLICY IF EXISTS`; partial unique index prevents duplicate active jobs |
| Correlation IDs | NOT NULL on jobs and steps; required on every event builder (throws when empty) |
| Platform DB only (ADR-017) | No tenant-database objects |

## Known limitations

- No execution path exists: nothing writes `provisioning_jobs` yet. Rows can only be created manually by a platform admin until Gate 3.2.
- `provider_key` defaults to `'unassigned'` until Gate 3.3 registers a concrete provider.
- Step timeouts are advisory constants; enforcement is Gate 3.2 work.
- `SecretReference` is a pointer type only; no secret store is wired.
